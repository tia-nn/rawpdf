## 2. regular runの分類

regular byteが続く限り（最長一致で）切り出し、内容で次の順に分類する（詳細設計6.2節）。

1. **数値**: 先頭に高々1個の符号（`+`/`-`）、続いて数字、`.`は高々1個。`.`があれば`Real`、無ければ`Integer`。符号が途中にある列（`1-2`）や指数表記（`123e5`）は数値にならない
2. **キーワード**: 下の表と完全に一致すれば、対応する`Kw*`
3. **どちらでもない**: `Unknown`

キーワードの照合は「長さでswitchしてからバイト比較」とする（詳細設計6.2節）。

| 長さ | バイト列 → 種別 |
|---|---|
| 1 | `R`→`KwR`、`n`→`KwN`、`f`→`KwF` |
| 3 | `obj`→`KwObj` |
| 4 | `true`→`KwTrue`、`null`→`KwNull`、`xref`→`KwXref` |
| 5 | `false`→`KwFalse` |
| 6 | `endobj`→`KwEndobj`、`stream`→`KwStream`（3章のstream本体モードに入る） |
| 7 | `trailer`→`KwTrailer` |
| 9 | `endstream`→`KwEndstream`、`startxref`→`KwStartxref` |

## 3. stream本体モードのトークン

`KwStream`を返した直後に、Lexerが自動で次の順に返す（基本設計4.2・4.3節、詳細設計6.2節）。

| 順 | 種別 | 内容 | フラグ | WBS |
|---|---|---|---|---|
| 1 | `Whitespace`（出ない場合もある） | 基本設計4.3節 Step 1に一致したEOL（非準拠の空白列を含む）。構造モードの空白スキャンは使わない | – | M3-2 |
| 2 | `StreamBody`（値51） | 本体。長さ0でも必ず出す | `endstream`が見つからなければ`UNTERMINATED` | M3-2 |
| 3 | （構造モードに戻る） | 本体から除いたEOLは、通常の`Whitespace`として次の`KwEndstream`に付く | | |

## 4. Lexerが出さないもの

- ノード種別（値100以上）すべて
- `MISSING`フラグ付きのトークン。これはパーサが作る幅ゼロの合成トークン（詳細設計7.3節）
