# PDFの`%%EOF`とファイルの終わり

`%%EOF`は、PDFのファイル（と、追記された更新の1つ1つ）の終わりを示す目印。字句としてはただのコメントで、このプロジェクトでもCommentトリビアとして読み、パーサがその中身を見て意味を与える。

## なぜ必要か

### PDFは後ろから読む形式

PDFのリーダーは、ファイルを先頭から順に読むのではなく、**末尾から**読み始める。

1. 末尾の近くで`%%EOF`を探す
2. その手前の`startxref`の後ろにある数値（xref表の位置）を読む
3. xref表とtrailer辞書をたどって、各オブジェクトの位置を知る

`%%EOF`は、この「末尾から読む」ときの足場になる。

### 増分更新（incremental update）で何度も現れる

PDFは、元のバイト列を書き換えずに、変更分を**ファイルの後ろに追記**して更新できる。これを増分更新という。電子署名したPDFに注釈を足すときなどに使われる（署名した範囲のバイト列を変えないため）。

追記した1回分の末尾にも、それぞれ`startxref`と`%%EOF`が付く。そのため、1つのファイルに`%%EOF`が何個も現れ得る。

```
%PDF-1.7
1 0 obj … endobj
xref … trailer … startxref 1234
%%EOF                ← 元のファイルの終わり
2 0 obj … endobj     ← 追記した更新
xref … trailer … startxref 5678
%%EOF                ← 更新の終わり（＝ファイルの終わり）
```

## どういう仕組みか

### 仕様上の扱い（ISO 32000）

- ファイルトレーラ（ISO 32000-1 7.5.5節）: ファイルの最後の行は、ファイル終わりの目印`%%EOF`だけを含む、とされている
- 増分更新（同7.5.6節）: 追記した部分も、元のファイルと同じく`trailer`・`startxref`・`%%EOF`で終わる
- 字句としては、`%`から行末までのコメント（同7.2.4節）と同じ形をしている。`%PDF-`のヘッダと同じく、「コメントの形をした、意味のある目印」の1つ

### 現実のファイルは揺れている

仕様どおりでないファイルが多いため、リーダーは`%%EOF`を緩く扱う。

- `%%EOF`の後ろに、空白や改行が付く（`%%EOF␠\r\n`など）
- `%%EOF`の後ろに、ゴミのバイト列が続く（転送やツールの都合で付いたもの）
- 旧PDF Reference（1.7）の付録Hにある実装ノートには、Acrobatが`%%EOF`をファイル末尾の1024バイト以内で探す、という趣旨が書かれている

## このプロジェクトでの扱い

### 字句：ただのComment（Lexerリファレンス1章）

Lexerは`%%EOF`を特別扱いしない。`%`で始まり、直後が`PDF-`でないので、行末の手前まで（CR/LFは含めない）を1つの`Comment`として切り出す。行末の空白は`Comment`に含まれる。

```
入力:   %%EOF␠\n
トークン: Comment "%%EOF␠"（長さ6）, Whitespace "\n"
```

### 木：次の実トークンのleading triviaになる（基本設計4.4節・4.5節）

トリビアはすべて直後の実トークンに付くので、`%%EOF`は次のSegmentの先頭トークン（ファイル末尾なら幅0の`EndOfFile`）のleading triviaに入る。専用のトークン種別は作らない。

```
… startxref 1234 \n %%EOF \n 2 0 obj …

KwStartxref, Integer "1234",
Integer "2"   (leading: Whitespace, Comment "%%EOF", Whitespace)   ← 次のSegmentの先頭
```

### 回復：Document/Segment階層の同期トークン（基本設計5.3節）

エラー回復で読み飛ばすとき、Document/Segment階層では「`%%EOF`パターンのComment」で止まる。トリビアの中身を照合するので、`TokenSource.hasEofCommentInTrivia()`（詳細設計6.3節）を使う。

### 「`%%EOF`パターン」の定義は自分で決める

設計書もリファレンスも、何を`%%EOF`パターンとみなすかを決めていない。上の「現実の揺れ」を踏まえて、次のような点を`hasEofCommentInTrivia`のdocコメント（TokenSourceのリファレンス）に書く必要がある。

- `%%EOF`ちょうどだけか、`%%EOF`の後ろの空白を許すか、`%%EOF`で始まれば何でもよいか
- 行頭であることを条件にするか（`1 0 obj %%EOF`のように行の途中にある場合）

同期トークンの判定は木の形（どこでSegmentが切れるか）を変えるので、緩すぎると普通のコメントで回復が止まり、厳しすぎると本物の`%%EOF`を見逃す。
