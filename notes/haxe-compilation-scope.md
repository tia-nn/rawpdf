# Haxeのコンパイル対象とDCE

Haxeのコンパイラは、クラスパスにあるファイルを全部コンパイルするわけではない。`--main`のクラス（と明示的に指定したもの）から**たどれるモジュールだけ**を読み込んで型検査する。さらにDCE（Dead Code Elimination：使われないコードの削除）が、出力からも不要なものを削る。

## なぜ知っておく必要があるか

TSの`tsc`は、`tsconfig.json`の対象にあるファイルを全部型検査する。その感覚のまま「`build.hxml`が通った＝全部のコードが型として正しい」と考えると、**どこからも参照されていないモジュールの型エラーを見逃す**。ライブラリ（パーサのように、`main`を持たず他から呼ばれるコード）を書くときに特に問題になる。

## どういう仕組みか

### コンパイル対象の決まり方

1. `--main Foo`で指定したクラスのモジュールを読む
2. そこから`import`や型の参照でたどれるモジュールを読む（再帰的に）
3. `--macro include("pkg")`などで明示的に指定されたパッケージのモジュールも読む
4. それ以外は、クラスパスにあっても**読まれない**（型検査もされない）

### DCEの3つのモード

| モード | 削るもの |
|---|---|
| `--dce std`（既定） | 標準ライブラリの使われない部分だけ |
| `--dce full` | 自分のコードも含め、使われないものすべて |
| `--dce no` | 何も削らない |

DCEは「読み込んで型検査した後」に出力から削る仕組みなので、型検査の範囲は上の「コンパイル対象」で決まる。`--dce no`にしても、読み込まれなかったモジュールが検査されるようにはならない。

## 具体例

```
src/
├── PDFCSTParser.hx   … main。Hello Worldだけ
└── Broken.hx         … public static function f():Int return "not an int";
```

`--main PDFCSTParser`でビルドすると、**成功する**。`Broken`はどこからも参照されていないので、読み込まれず、型エラーも報告されない（2026-11-12にrawpdfの雛形で確認）。

## このプロジェクトでの使われ方

- パーサ詳細設計2章の`build.hxml`は「型検査用（全モジュールをコンパイル）」としている。`--main`だけでは目的を満たさないので、パッケージ全体をコンパイル対象に含める指定が要る
- テスト（`test.hxml`）は、テストのクラスからたどれる範囲しか検査しない。テストの無いモジュールの型エラーは、`build.hxml`で拾う必要がある
- ライブラリ（parser・semantics）は`main`を持たない。`main`があるのは、テストのランナー・CLI・サーバーの入口

## 注意: エディタ用の設定には`--macro include`を入れない

`--macro include`は、ビルド用の`.hxml`（`build.hxml`）には要るが、エディタ（vshaxe）の補完・エラー表示用の設定（ルートの`display.hxml`）に入れると**構文エラーが表示されなくなる**。

- `--macro include`は**初期化マクロ**で、型付けが始まる前にパッケージ内の全モジュールを読み込む（パースする）
- そこで構文エラー（例: `Missing ;`）があると、マクロの途中で致命的なエラーになり、コンパイルがそこで止まる
- vshaxeはエラー表示のために「診断」（`--display <ファイル>@0@diagnostics`）をコンパイラに要求し、結果をJSONで受け取る。コンパイルが途中で止まると、JSONではなくただのエラー文字列が返るので、エディタには何も表示されない
- 型エラーは読み込みの後の型付けの段階で出るので、`include`があっても診断として表示される。そのため「構文エラーだけ出ない」という症状になる

エディタの診断は、開いているファイル自身を型付けして出すので、`--main`から参照されていないモジュールでも`include`なしで検査される。「未参照のモジュールも検査する」役目は`build.hxml`（`npm test`・CI）に任せればよい（2026-11-18にrawpdfの`Lexer.hx`で確認）。
